## 今回のユーザー指摘

管理画面の認証ログについて、以下の問題提起がありました。

```text
過去の認証ログとか、いつまでも表示し続ける？
過去のものは別枠から全表示できるようにして、直近のものを表示できるようにするべきでは。
そもそも、全ての認証動作が載ってないように思うけど。
```

判断としては妥当です。管理画面の通常表示に過去ログを無制限に並べ続けると、視認性が落ちます。一方で、監査・切り分け用には全件確認できる導線が必要です。

## 実装した対策

対象ファイル:

- `admin.html`
- `css/admin.css`
- `js/admin.js`
- `functions/_shared/review-auth.js`
- `js/version.js`

### 管理者認証イベント

- 初期表示は直近20件。
- `全件表示` ボタンで全件表示へ切替。
- 全件表示中はボタン文言を `直近表示` に変更。
- `ログ取得` は従来どおり全件JSONを保存。
- 表示件数メモを追加。

表示例:

```text
直近 20 / 53件を表示中。ログ取得は全件JSONを保存します。
```

### 限定レビュー認証イベント

- 初期表示は直近30件。
- `全件表示` ボタンで全件表示へ切替。
- 全件表示中はボタン文言を `直近表示` に変更。
- `ログ取得` は全件JSONを保存。
- 表示件数メモを追加。

表示例:

```text
直近 30 / 124件を表示中。未知IDの失敗は攻撃リストや個人情報を残さないため詳細には出さず、「認証振り返り」の件数だけに集計します。
```

## 認証動作ログの追加

`functions/_shared/review-auth.js` で、これまで詳細ログに残っていなかった以下を追加しました。

- 限定レビューのログイン成功
- 限定レビューのログアウト

ログイン成功時は以下のようなイベントを残します。

```js
{
  type: "login",
  result: "ok",
  email,
  reviewerId,
  reason: "password"
}
```

ログアウト時は以下のようなイベントを残します。

```js
{
  type: "logout",
  result: "ok",
  email,
  reviewerId,
  reason: "reader"
}
```

## あえて詳細ログに残さないもの

未知IDの失敗は、詳細な認証イベントには残していません。

理由:

- 攻撃者が投げたID候補を保存し続けることになる。
- 個人情報やメールアドレスらしき文字列を不要に蓄積する可能性がある。
- 認証成功や既知レビュワーの失敗と違い、運用上の個別追跡価値が低い。

代わりに、件数は「認証振り返り」側で集計する方針です。

## 今後の設計メモ

認証ログは次の3層に分けて考えるとよいです。

1. 画面の直近表示
   - 日常運用用。
   - 件数を絞って見やすくする。
2. 画面の全件表示
   - 軽い調査用。
   - 必要なときだけ開く。
3. JSONログ取得
   - 監査・保存・詳細調査用。
   - UI表示とは独立して全件を落とせるようにする。

この整理は、今後の操作ログ・アップロードログ・読書ログにも流用できます。ただしR2負担を増やさないため、ログ取得はユーザー操作時だけ行い、通常表示では必要最小限の取得・描画に留めるべきです。
