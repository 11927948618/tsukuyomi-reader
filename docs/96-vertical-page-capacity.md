# 縦書きの最終行を使う（0.1.248）

本文フォントは既存の読書設定で明朝・ゴシック・端末標準から選べる。標準を明朝のまま維持し、選択肢を「明朝（標準）」と表記する。ユーザーの選択を一律に上書きしない。

縦書きは固定された本文枠に収まる行数から安全用に1行を引いていた。この差引きを取り除き、左側の最終行も利用する。文字数側の禁則用余裕、見出しの予約領域、外側の余白、本文枠、横書きの安全用1行は維持する。

検証はreports/extra-line。0.1.247と変更後を同じサンプルで比較し、390×844・800×1280・1280×800で本文枠が変わらず容量が増えることを確認する。3種類のフォントと80/100/140%の文字サイズ、行間1.4/2.4で枠を維持し、ルビ、はみ出し、ページ間のsourceEnd/sourceStartの連続性を確認。動画・画面画像の追加撮影はしない。既存npm testも成功。

## 余白スライダーの表示と実際の幅を一致

スマホ・タッチ端末の単ページだけ本文幅を100−余白×0.5としていた旧処理を削除。説明・保存値が示す100−余白×2と統一する。「左右の追加余白」と明記し、左右それぞれの追加割合と本文幅を表示する。基本の外側余白と上下の余白はスライダーで変更しないことを補足する。

reports/marginsで変更前後の縦書き単ページを比較。390×844で最小・標準・最大の本文幅が旧351/340/316pxから351/309/211pxへ変わり、表示割合と一致。800×1280と1280×800でも実寸で確認。本文の高さ・上下余白・フォント選択を保ち、はみ出し・JSエラーなし、入力時の保存コールバックへ値が反映されることを確認した。

## スライダ最小時の1列微調整（0.1.256）

「縦書きを1列多く」がスライダの最小行間1.4を下回る計算になると無効化されていた。スライダの基準値は1.4〜2.4のまま維持し、追加1列の微調整のみ1emまで詰められるよう下限を分離した。オフ時は基準値に復元し、保存される基準値とオン／オフの仕組みは継続する。1emでも1列増やせない極端に狭い枠では、文字自体を重ねることはせず従来どおり無効になる。

詰めた状態ではルビを含む匿名行ボックスが計算より広がるケースがあった。微調整をオンにした縦書き本文だけ、ページャが作った各列を明示的な固定幅ブロックで配置する。文字・ルビの大きさと外枠は維持する。行番号表示でも同じ列幅を使う。

`reports/axis-margins/check_reader.py` に最小行間でのオン・オフと1列増加、基準値1.4の保持、ルビ付き本文の枠内収まりを追加。320×640、390×844、800×1280、1280×800、およびタブレット／PCの横並びと上下二段で確認する。既存の240%文字と独立余白の確認も継続。
