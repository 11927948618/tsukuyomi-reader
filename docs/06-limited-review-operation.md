# TsukuyomiReader 限定レビュー運用資料

作成日: 2026-05-18

賞応募候補作品を不用意に公開扱いにせず、友人・編集者候補など限られた相手に読んでもらうための運用整理です。ログの保存先と取得方法は `09-log-coverage-guide.md` を参照します。

## 結論

TsukuyomiReader は、友人に読んでもらうためのプラットフォームとして有効です。

ただし、賞応募候補作品を扱う場合は、通常の「立ち読み版」と「限定レビュー版」を分けます。

最小推奨構成:

- 公開版: 賞応募に使わない作品だけ置く
- 限定レビュー版: Cloudflare Access またはReader内パスワード認証で保護し、許可した相手だけ閲覧できるようにする
- 賞応募候補: 認証なしURL、一般公開、販売、頒布を避ける

## 前提

現在のTsukuyomiReaderは、立ち読みモードで `/api/books` または `books/manifest.json` から作品一覧を取得し、`published: true` の作品だけをLibraryに表示します。

この設計は「一般公開または限定公開の立ち読みサイト」としては自然です。ただし、賞応募候補を守るには、`published: true` の一般表示だけでは弱いです。

コピー禁止や右クリック抑制は、流出対策にはなります。しかし、未発表性の保持という観点では「閲覧できる人を制限しているか」の方が重要です。

## 公開扱いになりやすい運用

| 運用 | リスク | 理由 |
|---|---:|---|
| URLを知っていれば誰でも読める | 高 | 検索されなくてもWeb上で閲覧可能 |
| `published: true` で公開版Readerに表示 | 高 | Reader上で公開作品として扱われる |
| BOOTH / Kindle / note 等で販売 | 極高 | 自費出版・ネット公開扱いになりやすい |
| 文学フリマ等で頒布 | 極高 | 同人誌発表・頒布扱いになりやすい |
| SNSで本文リンク共有 | 高 | 公開範囲が制御できない |

## 比較的安全な運用

| 運用 | リスク | 用途 |
|---|---:|---|
| 自分用EPUB生成 | 低 | 推敲・組版確認 |
| ローカル環境でReader確認 | 低 | 表示確認 |
| 個別に友人へファイル送付 | 中低 | 内輪レビュー |
| 認証付きReaderで友人だけ閲覧 | 中低 | 限定レビュー |
| 編集者へ個別送付 | 中 | 持ち込み・相談資料 |

賞ごとの規定や編集部判断によって扱いは変わります。応募前に公式規定を再確認します。

## 推奨構成

### 公開版Reader

用途: 賞応募に使わない作品、公開済み作品、宣伝用サンプル。

- 通常の立ち読みモード
- `published: true` の作品を表示
- コピー抑制・右クリック抑制あり
- 賞応募候補は置かない

現在の公開版URL:

```text
https://tsukuyomi-reader-tachiyomi.pages.dev/
```

### 限定レビュー版Reader

用途: 友人・少数読者・編集者候補に未発表稿を読んでもらう。

- 公開版とは別のPagesプロジェクトまたは別サブドメインを用意する
- Cloudflare Access、またはReader内メールアドレス+パスワード認証でログイン必須にする
- 許可したメールアドレスだけ閲覧できるようにする
- One-time PIN方式なら、友人側にアカウント作成を求めずに済む
- `/api/books`、`books/manifest.json`、EPUB/TXT/PDF実体URLを未認証で読めないようにする
- R2の直リンク公開は避ける
- 閲覧データは読者同士には公開せず、管理側で一元保管・集計し、将来の文芸分析や作品改善に使うことを案内文に明記する
- SNS共有・再配布・引用禁止を明記する

限定レビュー版URLは未作成です。作成する場合は、公開版とは別名にします。

例:

```text
https://tsukuyomi-reader-review.pages.dev/
```

または独自ドメインを使う場合:

```text
https://review.example.com/
```

### ローカル確認版

用途: 作者本人の推敲・EPUB表示確認。

- 自分のPCやローカルサーバで確認
- 外部公開しない
- 賞応募候補の一次管理場所として使う

## Reader内パスワード認証

Cloudflare Accessがうまく動かない場合の代替認証です。Readerの起動時にメールアドレスまたは仮IDとパスワードを入力させ、ログイン後はHttpOnly Cookieのセッションで `/api/books`、本文API、表紙APIを保護します。

実際の操作手順だけを確認する場合は、`05-limited-review-auth-quick-guide.md` を先に見ます。

有効化する環境変数:

```text
TSUKUYOMI_REVIEW_PASSWORD_AUTH=true
TSUKUYOMI_REVIEW_AUTH_SECRET=十分に長いランダム文字列
```

`TSUKUYOMI_REVIEW_AUTH_SECRET` を省略した場合は `TSUKUYOMI_ADMIN_TOKEN` を補助値として使います。ただし管理トークンを変更すると既存パスワードも無効化されるため、限定レビュー版では専用の長いランダム文字列を推奨します。

運用手順:

1. 管理画面の `限定レビュー認証管理` で名前、仮ID、メールアドレスのいずれかを入力する
2. `PW発行` を押し、対象者の登録、閲覧許可、パスワード発行をまとめて行う
3. 表示されたパスワードを個別に送る
4. 読者はReader起動時にメールアドレスまたは仮IDとパスワードを入力する
5. 停止時は `PW無効化`、または状態を `閲覧保留` / `停止済み` にする

パスワードの平文は発行時だけ表示され、R2にはPBKDF2ハッシュを保存します。メール送信は行わないため、パスワードの送付は管理者が別途行います。

管理画面では、仮ID、メールアドレス、発行済み状態、最終ログイン、ログイン失敗回数、認証振り返り、認証イベントを確認できます。

標準の事前対策:

- ログインAPIは60秒に6回まで。超過時は5分ブロック
- メールアドレスまたは仮ID単位で5回失敗すると15分ロック
- パスワードは発行から7日で期限切れ
- ログインセッションは14日で期限切れ
- 同じメールアドレスまたは仮IDで10分以内に複数セッションが動いた場合、認証イベントへ `同時利用検知` を残す
- 限定レビュー認証が有効な場合、本文HTMLのローカルキャッシュ保存・復元を抑制する

同時利用検知は即ブロックではなく、管理ログへの記録です。本人がPCとスマホで開く可能性があるため、最初は警告に留め、必要に応じて `PW無効化` で止めます。

認証ログは「後で見返して判断材料になるもの」に絞ります。

- 有効なメールアドレスまたは仮IDに対するPW失敗、ロック発生、PW期限切れ、PW発行、PW発行失敗、PW無効化、PW無効化失敗、同時利用検知は詳細イベントとして残す
- 存在しないIDへの試行は、生のIDリストを残さず、未知ID失敗の件数だけを日別に集計する
- 成功ログインやログアウトは詳細イベントに溜めず、各エントリの最終ログイン時刻で確認する

調整用の環境変数:

```text
TSUKUYOMI_RATE_LIMIT_REVIEW_AUTH=6
TSUKUYOMI_RATE_LIMIT_REVIEW_AUTH_WINDOW_SECONDS=60
TSUKUYOMI_RATE_LIMIT_REVIEW_AUTH_BLOCK_SECONDS=300
TSUKUYOMI_REVIEW_LOGIN_FAILURE_LIMIT=5
TSUKUYOMI_REVIEW_LOGIN_LOCK_MINUTES=15
TSUKUYOMI_REVIEW_PASSWORD_DAYS=7
TSUKUYOMI_REVIEW_AUTH_SESSION_DAYS=14
TSUKUYOMI_REVIEW_CONCURRENT_WINDOW_MINUTES=10
```

## Cloudflare Accessを使う理由

限定レビューでは、自前で作品別IDや鍵付きURLを作るより、まずサイト全体をAccessで守る方が現実的です。

利点:

- サイト全体をログイン必須にできる
- メールアドレス単位で許可できる
- 許可リストから外せばアクセス停止できる
- 作品別ID方式より実装負荷が低い

## アクセス許可と読書ログの紐づけ

Cloudflare Accessの許可リスト全員を、TsukuyomiReaderが自動で取得できるわけではありません。

ただし、Access認証を通って実際にReaderへアクセスした人については、Functions側で認証済みメールアドレスを受け取り、読書ログへ管理用に紐づけられる場合があります。

有効化する環境変数:

```text
TSUKUYOMI_ACCESS_IDENTITY_ANALYTICS=true
```

有効化後、管理画面の読書ログに「Access別読書ログ（管理用）」が出ます。

この場合は匿名ログではなく、メールアドレスを含む個人情報ログになります。読者同士に進捗を公開するものではありませんが、限定レビュー版の案内文には、管理側が閲覧データを一元保管・集計し、文芸分析目的で使うことを明記します。

管理画面の「限定レビュー認証管理」は、Reader内パスワード認証では発行・無効化の実行欄です。Cloudflare Access運用では、Access側で追加・停止した相手を管理用に記録する欄として使います。

Reader内パスワード認証のメールアドレスを読書ログへ管理用に紐づける場合:

```text
TSUKUYOMI_REVIEW_PASSWORD_IDENTITY_ANALYTICS=true
```

この設定もメールアドレスを含む個人情報ログになります。

### 閲覧保留

Cloudflare Accessから相手を外すと、ログイン段階で拒否されるため、アクセス停止が比較的わかりやすくなります。

許可ユーザーを目立たず一時保留にしたい場合は、Access許可は残したまま、TsukuyomiReader側で個別に作品一覧を空にします。

有効化する環境変数:

```text
TSUKUYOMI_REVIEW_ACCESS_SOFT_BLOCK=true
```

この設定を有効にしたうえで、管理画面の `限定レビュー認証管理` で対象者を `閲覧保留` または `停止済み` にすると、Access認証済みメールアドレスが一致した場合だけ以下の挙動になります。

- `/api/books` は `[]` を返す
- `/api/books/:id/content` は `作品が見つかりません` として扱う
- `/api/books/:id/cover` も同様に見つからない扱いにする
- 読者側には保留理由を表示しない

Reader内パスワード認証では、`閲覧保留` または `停止済み` のメールアドレスは `TSUKUYOMI_REVIEW_ACCESS_SOFT_BLOCK` の有無に関係なく認証後のAPIで拒否されます。

これは完全な秘匿ではありません。通信内容や過去の記憶から状況を推測される可能性はあります。目的は、Cloudflare Accessの拒否画面を直接出さず、管理上の一時保留として扱いやすくすることです。

## 作品別ID方式について

作品別IDや鍵付きURLは後回しでよいです。

理由:

- URLが漏れると読めてしまう設計では弱い
- EPUB/TXT/PDF実体URLが見えると、鍵付きページだけ守っても意味が薄い
- 作品ごとの閲覧制御、期限、ログ、失効処理まで作ると実装負荷が高い

将来的にやるなら、以下の構成が必要です。

- R2上の本文ファイルを直接公開しない
- `/api/read/:workId` 経由で本文を返す
- API側で閲覧権限を確認する
- 期限付きトークンまたは閲覧者IDを管理する
- 作品ごとに公開範囲を設定する

## manifest設計案

通常の `published` とは別に、レビュー用フラグを持たせる案です。

```json
{
  "id": "sekai-chizu-yohaku",
  "title": "世界地図の余白",
  "published": false,
  "reviewOnly": true,
  "reviewGroup": "friends",
  "awardCandidate": true,
  "path": "books/works/sekai-chizu-yohaku.epub"
}
```

意味:

- `published`: 一般公開するか
- `reviewOnly`: 限定レビュー対象か
- `reviewGroup`: 閲覧できるグループ
- `awardCandidate`: 賞応募候補として扱うか

ただし、フラグだけでは保護になりません。Cloudflare Access等で、サイトまたはAPI自体を守る必要があります。

## 運用ルール

賞応募候補作品は、以下を原則にします。

1. 公開版Readerには置かない
2. `published: true` にしない
3. 認証なしURLでは読めないようにする
4. R2直リンクを公開しない
5. 友人には再配布・SNS言及禁止を明記する
6. 読んでもらう相手を記録する
7. 応募前に賞の公式規定を再確認する
8. 応募後、結果が出るまでは公開・頒布しない

## 友人向け案内文

標準:

```text
未発表原稿の確認用リンクです。
賞応募や編集部相談に使う可能性があるため、本文・URLの再配布、引用、スクリーンショット共有、SNSでの言及はしないでください。
文芸分析のため、どの作品をいつ開いたか、どこまで読んだか、読了したかを記録することがあります。
この情報は他の読者には公開せず、管理側で保管・集計します。
感想は個別に送ってください。
```

軽め:

```text
まだ未公開の試作稿です。
URLや本文は外に出さず、感想だけ個別にもらえると助かります。
読書状況は、作品改善のために確認することがあります。
読書状況は他の読者には公開しません。
```

## 段階的実装方針

### 第1段階: 非公開EPUB管理

- 作品をEPUB化する
- ローカルまたは自分用Readerで確認
- 公開しない

### 第2段階: 限定レビュー版

- review用サブドメインまたは別Pagesプロジェクトを用意
- Cloudflare Accessを設定
- 友人メールだけ許可
- 賞応募候補を置く

### 第3段階: 公開版と分離

- 公開版Readerには賞に使わない作品だけ置く
- 賞候補はレビュー版のみに置く
- manifestで `published` と `reviewOnly` を分ける

### 第4段階: 作品別制御

必要になったら実装します。

- 作品別閲覧権限
- 期限付きリンク
- 閲覧ログ
- レビュー依頼ごとの個別管理

## 現時点の推奨判断

今すぐ作品別IDを作り込む必要はありません。

最優先:

1. 賞応募候補を公開版に置かない
2. 自家製EPUBで読書体験を確認する
3. 友人レビューが必要ならCloudflare Accessで保護する
4. 公開版とレビュー版を分ける

## 注意

この資料は実務上の整理であり、賞応募における未発表性を保証するものではありません。最終判断は各賞の応募規定と、必要に応じて編集部・主催者への確認に従います。
