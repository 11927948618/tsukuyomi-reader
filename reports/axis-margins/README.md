# Reader 0.1.249: 余白・文字サイズ

左右余白と上下余白を独立設定。既存左右キーを維持し、新規pageVerticalMarginPercentは未設定時7%。上下各0〜20%（viewport高さ基準）で本文の利用可能高さを再計算する。全体・本別の設定保存、viewer profile、ZIP書き出しにも含める。上下が変わらない旨の注釈は削除。

文字サイズは80〜240%。大文字・狭い本文枠では1列／少数字数までページ容量を減らせるようにし、最低行数を強制しない。明朝・ゴシック・端末標準の選択は維持。

「縦書きを1列多く」は文字サイズと枠を変えず、次の1列が入る行間を算出。初版では1.4未満を許可しなかったが、0.1.256ではスライダ基準値（最小1.4）と追加1列の微調整下限（1em）を分離。オンで1列増やし、オフで元の行間に戻る。ルビが匿名行ボックスを広げるのを避けるため、微調整中の縦書きだけ各列の幅を明示する。文字・ルビのサイズは変えない。行間スライダは0.01刻みで基準値を示す。左右余白の縮小でも列数を調整可能。

設定なしの旧データで左右余白が最大20%になるnull変換も修正。既存の数値0や旧wrapWidthPercentは維持する。

check_reader.pyで320×640、390×844、800×1280、1280×800のChromiumを確認。上下だけで高さ、左右だけで幅が変わること、設定パラメータ、一列追加、240%の実測フォントサイズ38.4pxと縦横の収まりを確認。ルビ付きの段落・会話文を使った機能確認であり、物理端末・全作品・全モードの網羅試験ではない。ページャの既存4テストも通過。

補足：改行のないルビ付き長大段落を反復した別fixtureでは、変更前と同様のfit warningがある。今回の通常段落fixtureの合格をそのケースの解決と扱わない。

この文書は0.1.249時の確認から継続更新。0.1.256では最小行間での1列追加・オンオフ復元・ルビ付きの収まりを単ページ／見開き／上下二段で追加確認。
