# Reader 0.1.250：作者フォルダと一括管理

## 読者側

作品一覧は作者フォルダを開いて選ぶ。作者内のfolderPathも下位フォルダとして表示。作者未設定は専用の表示名へまとめ、書籍・作者情報付きWebコンテンツの既存起動ボタンを保持。検索時は該当作品のフォルダを開く。通常カードの作品ID・本文URL・ローカルの読書位置は変更しない。

## 管理側

パンくず、作者・フォルダの一覧、作品選択、フォルダ作成、名前変更／移動、選択作品の移動を提供。本文オブジェクトを移動せず、作者とfolderPathのメタデータだけ更新する。空フォルダはR2カタログのfolders配列で保存する。既存の個別編集・公開操作はフォルダ内の作品カードから利用可能。

フォルダ選択は「作者/分類/作品.txt」等の構造から推定。ZIP内のTXT/Markdown/EPUB/PDFの集合にも対応。EPUB自体は展開しない。プレビューの作者・作者内フォルダ・作品名を修正してから実行する。フォルダ選択非対応のブラウザではZIPを使用する。ブラウザのフォルダ選択で取得できない空ディレクトリは検出できない。

新規ファイルのIDは内容ハッシュを基に生成。同じ内容の重複を取込内で拒否する。内容を変更したファイルを再取込すると新IDとなる。既存作品の差し替えは従来の個別編集から行う。同IDを持つバックアップはcreateOnlyで既存を上書きせずスキップ。処理は逐次で、停止は次の作品から。途中失敗時は完了分を残し、再試行時に同IDを上書きしない。

## バックアップと復元

表示中の公開／限定レビューの区分ごとに、全作品の本文・表紙・メタデータ・空フォルダをZIPへ保存。非公開本文・表紙の取得は新しい管理認証必須のfile APIを使う。リクエストの任意キーをR2から読む方式にはしない。バックアップ中は区分と一覧をスナップショットする。

`tsukuyomi-library.json` schemaVersion=1、files/{id}.{format}、covers/{id}.{ext}を収録。本文と表紙のSHA-256を保存し、復元前に照合する。WebコンテンツのZIPはバックアップ内でそのまま保持し、既存のWebapp検証を通して復元する。

復元先は限定レビュー・非公開。一般公開一覧から取り込もうとした場合は限定レビューへの切替を案内する。元の公開状態はバックアップに保存するが自動再公開しない。公開区分をまたいで黙って上書きしない。

一括上限：作品500件、合計256MB、本文・表紙各64MB。ZIP内エントリは1500以下。上限に合わないデータを復元不能なバックアップとして出力しない。巨大な書庫全体のストリーム処理、全区分を一つにまとめるバックアップ、読者端末内だけの読書履歴・認証情報・Reader設定の管理バックアップは対象外。従来の個人読書バックアップは維持する。

## 確認と制約

Node：パス・トラバーサル拒否、カタログ通常更新による空フォルダ保持、認証付きサブツリー移動でID/本文キー保持、非公開ファイルの認証、createOnlyの衝突拒否、作品移動のメタデータ保持。既存8テストファイルも通過。

Chromiumの画面操作とモックAPI：フォルダナビ・作品移動、本文/表紙/空フォルダのZIP保存→復元、同IDスキップ、破損ハッシュ拒否、実ディレクトリ選択、作者→作品表示を確認。実R2への書込みや実機のフォルダ選択は未実施。ブラウザ内のZIP処理はメモリを使うため、初版は上記上限を設ける。カタログの同時編集に対するトランザクション保証は既存方式と同様に未実装。
